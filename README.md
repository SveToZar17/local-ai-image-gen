# Локальный AI-генератор картинок

Локальный AI-генератор картинок. Работает **полностью на вашем компьютере**,
на вашей видеокарте — без облаков, без подписок, без сторонних серверов.

Пользоваться можно через:

- 🤖 Telegram-бота
- 🌐 веб-интерфейс в браузере

Внутри — ComfyUI для генерации картинок
и опциональная локальная LLM (Llama 3.2 3B), которая улучшает ваши текстовые описания
перед генерацией.

Проект с открытым исходным кодом (лицензия MIT), сделан для портфолио и для души.

## 1. Что вам понадобится

- Windows 10/11, Linux или macOS (для генерации нужна NVIDIA-видеокарта; macOS подойдёт
  только для тестирования без GPU-ускорения).
- Видеокарта NVIDIA с 4+ ГБ видеопамяти (VRAM). Чем больше — тем лучше картинки и быстрее генерация.
- Установленные Docker и Docker Compose.
- Установленные драйверы NVIDIA и
  [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/install-guide.html)
  (нужен, чтобы Docker-контейнеры видели вашу видеокарту).
- Аккаунт в Telegram, если хотите бота (это бесплатно и займёт 2 минуты).

## 2. Установка Docker

1. Скачайте и установите **Docker Desktop**: https://www.docker.com/products/docker-desktop/
2. Запустите Docker Desktop и дождитесь, пока значок в трее станет зелёным.
3. **Только для Windows с NVIDIA:** убедитесь, что в Docker Desktop включена поддержка WSL2
   (Settings → General → "Use the WSL 2 based engine").
4. Установите NVIDIA Container Toolkit по инструкции выше — без него видеокарта не будет видна
   внутри контейнеров.
5. Проверьте, что всё работает:

```bash
docker run --rm --gpus all nvidia/cuda:12.4.1-base-ubuntu22.04 nvidia-smi
```

Если вы видите таблицу с информацией о видеокарте — всё в порядке.

## 4. Скачивание моделей для генерации картинок

Модели — это файлы, которые "умеют рисовать". Их нужно скачать один раз, они не входят в
репозиторий (слишком большие). Выберите модель по объёму видеопамяти вашей видеокарты:

| VRAM видеокарты | Рекомендуемая модель | Размер | Где скачать |
|---|---|---|---|
| 4–6 ГБ | Stable Diffusion 1.5 | ~2 ГБ | [Hugging Face](https://huggingface.co/runwayml/stable-diffusion-v1-5) |
| 8–12 ГБ | SDXL Base 1.0 или SDXL Turbo | ~7 ГБ | [SDXL Base](https://huggingface.co/stabilityai/stable-diffusion-xl-base-1.0) · [SDXL Turbo](https://huggingface.co/stabilityai/sdxl-turbo) |
| 16+ ГБ | Flux.1-schnell (лучшее качество)¹ | ~23 ГБ | [Hugging Face](https://huggingface.co/black-forest-labs/FLUX.1-schnell) |

¹ **Важно:** стандартный `workflows/default_workflow.json` рассчитан на SD/SDXL. Для Flux нужен
отдельный workflow с другими узлами. Если вы не уверены — начните с SDXL Base.

Также стоит заглянуть на [CivitAI](https://civitai.com/) — там много стилизованных моделей
(аниме, реализм, конкретные художественные стили) от сообщества.

**Проще всего** — воспользоваться готовым скриптом, он сам скачает выбранную модель в нужную папку:

```bash
chmod +x scripts/download_models.sh
./scripts/download_models.sh
```

После скачивания откройте `workflows/default_workflow.json` и укажите точное имя вашего файла
модели в поле `ckpt_name` (узел `CheckpointLoaderSimple`). Например:

```json
"ckpt_name": "sdxl-base-1.0.safetensors"
```

> У вас RTX 4060 Ti с 16 ГБ VRAM? Смело берите SDXL Base, SDXL Turbo — с таким запасом
> видеопамяти всё это будет работать комфортно.

## 5. Скачивание LLM для улучшения промптов (опционально)

LLM (Llama 3.2 3B) превращает короткое описание вроде "кот в космосе" в подробный
промпт с деталями освещения, стиля и композиции. Работает **на процессоре**, поэтому не
занимает видеопамять, нужную для генерации картинок.

Если у вас слабый ПК или мало оперативной памяти — просто пропустите этот шаг и поставьте
`ENABLE_LLM_PROMPTER=false` в `.env` (шаг 6). Бот и веб-интерфейс продолжат работать, только
будут использовать ваш промпт как есть, без улучшения.

```bash
chmod +x scripts/download_llm.sh
./scripts/download_llm.sh
```

## 6. Настройка .env

В корне проекта уже лежит файл-пример `.env.example`. Скопируйте его и откройте в любом текстовом редакторе:

```bash
cp .env.example .env
```

Заполните хотя бы `TELEGRAM_BOT_TOKEN` (как получить — см. шаг 8) и при желании отключите LLM:

```bash
TELEGRAM_BOT_TOKEN=ваш_токен_от_botfather
ENABLE_LLM_PROMPTER=true   # или false, если хотите отключить
```

## 7. Запуск

Из корня проекта:

```bash
docker compose up -d --build
```

Первый запуск может занять несколько минут — Docker соберёт образы и скачает ComfyUI.
Проверить, что всё запустилось:

```bash
docker compose ps
```

Все четыре сервиса (`comfyui`, `ai-gateway-api`, `ai-telegram-bot`, `ai-web-ui`) должны быть
в статусе `running` / `healthy`.

Остановить всё:

```bash
docker compose down
```

## 8. Настройка Telegram-бота

1. Откройте Telegram и напишите [@BotFather](https://t.me/botfather).
2. Отправьте команду `/newbot` и следуйте инструкциям (придумайте имя и username бота).
3. BotFather выдаст вам токен вида `123456789:ABCDefGhIJKlmNoPQRsTuVwXyZ`.
4. Вставьте этот токен в `.env` в переменную `TELEGRAM_BOT_TOKEN`.
5. Перезапустите бота: `docker compose up -d --build telegram_bot`.
6. Найдите своего бота в Telegram по username и напишите `/start`.

Дальше просто отправляйте боту текстовые описания картинок — он пришлёт готовое изображение.
Команда `/template` позволяет выбрать стиль промпта (для презентаций, соцсетей, дизайна).

> **Важно:** не запускайте два экземпляра бота с одним токеном одновременно — Telegram
> вернёт ошибку `Conflict`. Если видите эту ошибку в логах, остановите дубликат:
> `docker compose stop telegram_bot`.

## 9. Использование веб-интерфейса

Откройте в браузере: **http://localhost:8080**

Введите описание, выберите шаблон и размер, нажмите "Сгенерировать". Готовая картинка
появится прямо на странице.

> Если открываете с другого устройства в вашей локальной сети — используйте IP-адрес
> компьютера с сервером вместо `localhost`, например `http://192.168.1.50:8080`.
> В этом случае укажите IP в переменной окружения при тестировании:
> `API_BASE_URL=http://192.168.1.50:8000 python scripts/test_generation.py`

## 10. Тестирование

Проверить, что всё работает, можно скриптом:

```bash
pip install requests
python scripts/test_generation.py --prompt "рыжий кот в скафандре на луне"
```

Скрипт проверит доступность сервисов, отправит запрос на генерацию и сохранит результат в
`test_result.png`.

**Ориентир по скорости на RTX 4060 Ti 16GB:**

- SD 1.5, 512×512, 25 шагов: ~3–5 секунд
- SDXL Base, 1024×1024, 25 шагов: ~10–15 секунд
- Flux.1-schnell, 1024×1024, 4 шага: ~8–12 секунд (требует отдельный workflow)
- Загрузка LLM (CPU) в память: ~2–5 секунд при первом запросе, дальше улучшение промпта
  занимает 1–3 секунды

(Точное время зависит от модели, разрешения, количества шагов и загрузки процессора.)

## 11. Проблемы и решения

**Контейнер `comfyui` не запускается / не видит видеокарту**
Проверьте, что установлен NVIDIA Container Toolkit и что команда из шага 2
(`docker run --rm --gpus all ...`) отрабатывает без ошибок.

**Ошибка "CUDA out of memory"**
Слишком высокое разрешение или модель для вашей VRAM. Уменьшите размер картинки в
`.env` / веб-интерфейсе или выберите менее требовательную модель (см. таблицу в шаге 4).

**Telegram-бот не отвечает**
Проверьте логи: `docker compose logs -f telegram_bot`. Частая причина — неверный токен
в `.env` или бот не был перезапущен после изменения `.env`. Также убедитесь, что не запущено
два бота с одним токеном.

**LLM не загружается**
Убедитесь, что файл модели скачан (`scripts/download_llm.sh`) и путь в `.env`
(`LLM_MODEL_PATH`) совпадает с реальным именем файла. Логи: `docker compose logs -f api`.

**Генерация работает, но картинки "мусорные"**
Обычно это неправильно указанное имя модели в `workflows/default_workflow.json`
(`ckpt_name`) или несовместимость модели (например, SD 1.5 workflow с SDXL-моделью).

## 12. Структура проекта

```
local-ai-image-gen/
├── docker-compose.yml       # связывает все сервисы вместе
├── .env.example             # пример настроек (скопируйте в .env)
├── LICENSE                  # MIT
├── api/
│   ├── main.py              # FastAPI-шлюз: принимает запросы, общается с ComfyUI
│   ├── llm_prompter.py      # улучшение промптов через локальную LLM
│   ├── requirements.txt
│   └── Dockerfile
├── telegram_bot/
│   ├── bot.py               # Telegram-бот
│   ├── requirements.txt
│   └── Dockerfile
├── web_ui/
│   └── index.html           # веб-интерфейс (одностраничный, без сборки)
├── workflows/
│   └── default_workflow.json # шаблон графа генерации для ComfyUI
├── scripts/
│   ├── download_models.sh   # скачивание моделей SD/SDXL
│   ├── download_llm.sh      # скачивание LLM для улучшения промптов
│   └── test_generation.py   # тестовый прогон всего пайплайна
├── models/                  # сюда скачиваются модели (не входит в git)
├── llm_models/              # сюда скачивается LLM (не входит в git)
└── output/                  # сюда сохраняются сгенерированные картинки
```
